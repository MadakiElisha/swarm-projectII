SWARM-PROJECT II

A decentralized, vendor-agnostic cognitive drone swarm — five multirotors, no central brain, real ArduPilot physics, operator-grade 2D/3D GCS, regression-gated. · MIT · Madaki Elisha · stefannelisha@gmail.com · github.com/MadakiElisha/swarm-projectII

1 · Essence

Each drone is an intelligent actor: it bids on tasks using distance + wind-aware energy belief, vetoes unsafe work, relinquishes and hands over when depleted, climbs to heal mesh links, and pursues moving targets from shared data. Coordination is a replicated contract-net auction with an elected, kill-tolerant leader — kill it and a standby promotes in ~3 s with mirrored state. Everything runs on ArduPilot SITL today and is shaped for real hardware via a VehicleAdapter backend abstraction (sim↔real swap = one parameter; a proprietary adapter implements the same interface and the stack above never changes).

3 · Mission pipeline

detect → auction → converge → declare → pursue → release

  • Detect: YOLO person sightings → amber RESCUE suggestions; human confirms (HITL).
  • Auction: bids = distance + wind-aware battery belief; mesh reachability gate; unsafe bids vetoed locally.
  • Converge: simultaneous lift, rotating 300 m ring, staggered altitudes, GO/NO-GO preflight.
  • Declare: drones self-report ENROUTE / ON_STATION / RELEASED (radial band test); leader emits exactly one PERIMETER_FORMED / DEGRADED / RELEASED event → GCS banner + logs.
  • Pursue: INTERCEPT re-centers the ring on the live TargetTrack; two lead-pursuit cutters; stale-track orbit hold.
  • Release: human command, battery relinquish, or hold expiry → RTL.

6 · Quality gates

  • scripts/regression.sh — self-flying acceptance gate: C1 telemetry×5 · C2 mesh links · C3 five replicas · C4 five assignments · C5 PERIMETER_FORMED <240 s @ 120 m band · C6 mover auto-start; emits reports/run_*.png acceptance graphs + run history.
  • pytest cores; boundary validation on every inbound field; crash-proof handlers; abort channel; two-layer watchdogs; idempotent auctions (lossy-link-safe retries).
  • One-command ops: scripts/swarm_up.sh / swarm_down.sh with health summary.

7 · Hardware plan

Per drone: Pixhawk (ArduPilot 4.5+) + Jetson Orin Nano + CSI cam + mesh radio (802.11s/batman-adv or Mesh Rider) + 915 MHz C2 failsafe. Bandwidth rule: detections cross the mesh; video is pulled selectively (RTSP/WebRTC), never on the ROS bus. Phasing: P1 bench (1 real FC + 4 SITL, one launch file, two worlds) → P2 1-real + 4-SITL flight → P3 3 real → P4 5-real field mesh test.
